Joshua Tree Fire Explorer

An exploration layer over the 2025 Eureka and Black Rock fires in Joshua Tree National Park — burn severity, vegetation, and fire history, queried in plain language.

This is not the authoritative analysis

The numbers of record for post-fire reporting come from SchmidtDSE/jotr_2025_fire_eda, an R analysis using exact area-weighted raster extraction (exactextractr). Its rendered report is published here.

That analysis answers seven fixed questions. This app answers arbitrary ones against the same data, and computes areas differently — expect agreement to within roughly a percent, not to the digit. Where the two disagree, the R analysis is correct. If you are pulling a number for a report, pull it from there.

Data sources

LayerSource
Burn severity (RBR) Schmidt DSE Fire Severity Tool, Sentinel-derived, ~15 m
Vegetation map units NPS Vegetation Mapping Inventory Project for Joshua Tree NP — 16,499 polygons, 67 units
Fire perimeters CAL FIRE FRAP fire perimeters, 2025 release
CWHR habitat types CAL FIRE FRAP FVEG 2022, California Wildlife Habitat Relationships classification, 30 m statewide

What RBR means

Severity is the Relativized Burn Ratio, from Parks, Dillon & Miller (2014):

RBR = dNBR / (NBRprefire + 1.001)

where NBR = (NIR − SWIR) / (NIR + SWIR), an index that drops sharply when fire removes vegetation moisture and chars soil. Higher RBR means more severe. Values at or below zero mean no detected change.

RBR is used here rather than dNBR or RdNBR because RdNBR becomes unstable wherever pre-fire NBR approaches zero — the normal condition in sparse Mojave desert vegetation. Severity class breaks (low / moderate / high) are calibration-dependent and are deliberately not published here.

Two vegetation classifications

The NPS map units and the CWHR habitat types classify the same ground by different methods at different times. They disagree, and that is not an error. Inside the park, the NPS polygons are field-based and resolve individual stands, so they are what the fire analyses use. CWHR is a 30 m statewide raster — useful for context beyond the park boundary, too coarse for fire-scale work (its native hex cell is ~1.5 ha, so the entire 87 ha Eureka Fire is about 58 cells).

The map colors NPS polygons by their NVCS Group — the published classification hierarchy shipped with the NPS geodatabase — rather than by the 67 individual map units, which is more categories than any legend can carry. Hover any polygon for its full map unit name.

How it works

Everything is static. GitHub Pages serves the page, the configuration, the STAC collection and the data. The map and agent load from CDN (geo-agent). Questions are answered by an LLM writing DuckDB SQL against cloud-native files, through an MCP server.

Experimental endpoint. The severity rasters are read live with DuckDB's raster community extension rather than being pre-aggregated to a hex grid, which only exists on an experimental MCP deployment. That endpoint carries no uptime guarantee. If vegetation questions work but severity questions fail, that is why.

You supply your own model key; nothing is stored server-side.
